## 2.1 The environment: uv, pyproject.toml and uv.lock

Python programs depend on third-party libraries. So that they do not get mixed with the libraries of other projects, every project has its own **virtual environment** (a `.venv` folder with an isolated "box" of libraries). `uv` is the tool that creates that box and takes care of it.

@code core/pyproject.toml:1-13 "core/pyproject.toml · the project's identity card"

| File / command | What it does |
|---|---|
| `pyproject.toml` | Declares the project name, the minimum Python version and the dependencies. You edit it (or let `uv` edit it). |
| `uv.lock` | Records the exact versions of everything that was installed, so anyone reproduces the same environment. Generated by `uv`; never edited by hand. |
| `uv sync` | Installs exactly what `uv.lock` says. |
| `uv add package` | Adds a dependency (updates `pyproject.toml` and `uv.lock`). |
| `uv run src/main.py` | Runs the program inside the project's environment. |

The api has its own `pyproject.toml` and `uv.lock`, and its own `.venv`. Each Python project is independent: that is why the commands of Chapter 11 start with `cd core` or `cd api`.

::: lesson A dependency that was missing
When SQLAlchemy 2.1 was turned on in asynchronous mode, the program failed: it requires the `greenlet` library, which the new version stopped installing by itself. The fix was to ask for the "extra" `sqlalchemy[asyncio]` (see the list above). Moral: an import error says exactly what is missing, so read the message to the end.
:::

## 2.2 Modules, packages and imports

A `.py` file is a **module**. A folder with an `__init__.py` file is a **package**: a module that groups other modules. To use something from another place we use `import`:

```python title="Three ways to import (examples from the project)"
from domain import Prompt                   # from the package 'domain', bring the class Prompt
from .status import PromptStatus            # one dot = 'the neighbor file of this one'
from ..events import PromptCreated          # two dots = 'the folder above'
```

::: project Why does "uv run src/main.py" work?
When you run a script, Python puts the folder of that script in the list of places where it looks for modules. Since the script is `src/main.py`, the folder `src/` enters the search, and `import domain` finds `src/domain/`. To run anything else from the root of the project we use `PYTHONPATH=src`, which gives Python the same hint.
:::

## 2.3 Types: saying what each thing is

In Python you can (and in this project we always do) annotate the expected type of each value. Python does not enforce it when running, but tools such as `pyright` check everything beforehand, and the code becomes its own documentation.

| Written | Reading it in plain English |
|---|---|
| `name: str` | "name is a text" |
| `versions: list[PromptVersion]` | "versions is a list of PromptVersion" |
| `active_version_number: int \| None` | "an integer or nothing (`None`)": here, "no active version" |
| `def delete(self) -> None` | "delete is a function that returns nothing" |
| `async def get(...) -> Prompt \| None` | "an asynchronous function that returns a Prompt or `None`" |
| `dict[str, Any]` | "a dictionary whose keys are texts and whose values can be anything" |

## 2.4 Classes, dataclasses and enums

A **class** is a mold for objects: it gathers data (attributes) and behaviors (methods). Inside it, `self` means "this very object". Four variations appear all the time:

- `@dataclass`: the `@` is a *decorator*, a sticker glued on the class. This one generates the constructor and the comparison automatically, saving repetitive code.
- `frozen=True`, inside `@dataclass`: makes the object immutable. Once created, it can never change.
- `Enum` / `StrEnum`: a closed list of valid options (such as the states of a prompt).
- `@property`: turns a method into something you read like an attribute and that cannot be changed from outside.

Read the listing as a sentence: "a `PromptVersion` is an immutable stamp with a number, a content, a date and an id; when it is created, it refuses a number lower than 1 and a blank content". That is exactly what the code says.

## 2.5 Protocol: contracts without inheritance

Python uses the idea of **duck typing**: "if it walks like a duck and quacks like a duck, it works as a duck". A `Protocol` describes the *shape* an object must have (which methods, with which signatures) without forcing anyone to inherit from anything. Any class that has those methods fulfils the contract.

@code core/src/port/prompt_repository.py:8-21 "core/src/port/prompt_repository.py · a contract"

The `...` in place of a body means "here we only declare; the implementation comes from elsewhere". This technique is the basis of the *ports* we will see in Chapter 3.

## 2.6 async / await: the waiter who serves several tables

A good part of the time of a service is waiting: waiting for the database to answer, waiting for a message to arrive over the network. Instead of standing still, the program can serve another task while it waits. That is **asynchronous programming**.

::: analogy The waiter
A waiter who serves one table at a time, standing in front of the kitchen until the dish is ready, serves few people. An asynchronous waiter takes the order, goes to the next table and comes back when the kitchen calls. It is still one waiter, but nobody waits for nothing.
:::

| Word | Meaning |
|---|---|
| `async def f(): ...` | Defines a function "that can wait": a *coroutine*. |
| `await something()` | "I wait for the result, but meanwhile the program may serve other tasks." |
| `asyncio.run(main())` | Opens the "restaurant": starts the engine that coordinates all asynchronous tasks. |
| `asyncio.Lock()` | A "single key": only one task at a time can hold it (we will see why in Chapter 6). |

::: project Why is the project asynchronous?
Because its two sources of waiting, NATS (network) and SQLite (disk), have asynchronous libraries (`nats-py` and `aiosqlite`). The service then handles many messages without freezing. The api is asynchronous too: FastAPI runs your `async def` routes on the same kind of engine, and the browser front end has its own version of the idea (`async`/`await` and *promises* in TypeScript).
:::

## 2.7 Context managers: "with" and "async with"

The `with` block guarantees that something is opened and closed properly, no matter what happens in the middle. Think of a door that closes by itself when you leave. In the project, the database transaction works like this:

```python title="Pattern repeated in the use cases (shortened)"
async with self._uow:
    prompt = await require_prompt(self._uow.prompts, command.prompt_id)
    ...
    await self._uow.commit()
```

If anything goes wrong before `commit()`, when the block ends the transaction is undone automatically. We will come back to this slowly.

## 2.8 Exceptions: when something cannot continue

`raise` interrupts the function and signals a problem; `try / except` catches the signal to handle it. The project defines its own exceptions for each business rule that gets violated, for example `PromptDeletedError` ("you cannot do this to a deleted prompt"). Names like these make the error self-explanatory and allow handling it in a specific way.

## 2.9 A mini-dictionary of symbols

| Symbol | Meaning |
|---|---|
| `_name` | Convention: "internal use, do not touch from outside" (e.g. `self._status`). |
| `__init__` | The constructor: runs when the object is created. |
| `*, activate: bool = False` | The `*` forces you to write `activate=True` by name; `= False` is the default value. |
| `{...}` | A dictionary (key: value pairs) or a set, depending on the content. |
| `f"text {x}"` | A text with embedded values (an *f-string*). |
| `x[T]` or `list[str]` | A *generic*: a container or wrapper that is parameterized by a type. |
| `[a for a in items if ...]` | A *comprehension*: builds a list by transforming and filtering another one. |
