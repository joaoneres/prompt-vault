Every NATS subject becomes one use case, which calls one domain method. The api exposes the same operations as HTTP routes, and the front end has a screen for each. Click a row to see the payload, the reply, the events, the possible errors and a ready command to copy.

Notice: deactivate() and reactivate() exist in the domain and in the simulator, but have no use case and no subject in the system. That is why the events PromptDeactivated and PromptReactivated are never published by the service today.

Every failure ends as the same standard JSON and, in the browser, as a toast. Pick a situation to see where it starts, which code travels, which exception the api raises and which HTTP status the user gets.

Rule of thumb: clients rely on the code, never on the message. The messages are written for people (in Portuguese, in this project); the codes are the contract.

main.py of the core is the only file that knows every layer: it creates the pieces and connects them, in this order. Step forward and watch the object graph grow.
